# ADR 0001：V2 业务核心、权限与迁移边界

日期：2026-09-09。状态：采用。适用阶段：P1–P3。

## 背景

legacy `52d0a92` 使用共享口令、单一管理员、全局邮箱去重和部门字段。新增桌面入口前，需要先明确用户身份、账号归属和运行实例边界，避免把现有共享访问模式带入新版。

## 决策

- Python 模块化单体；domain 定义资源和规则，application 编排用例，infrastructure 实现仓储/上游适配，api 与 local/cli 负责入口，runtime 完成依赖组装。
- 新 API 为 `/api/v1`。资源路径采用 `/workspaces/{workspace_id}/accounts/{account_id}`；同一 API 主版本允许新增可选字段，破坏性更改增加主版本。桌面先协商版本和 capabilities，再执行操作。
- User 与第三方 Account 分离。账号 UUID 不随邮箱、标签和凭证轮换变化；Workspace 是数据归属边界。
- Owner/Admin 管理整个空间，Member 默认无账号权限，Viewer 只能查看被授予 view 的账号；use 包含 view 并允许刷新/切换。任免 Admin、转移 Owner 和删除空间只允许 Owner。完整矩阵以[实施计划](../plans/v2-architecture.md#41-固定角色与账号授权矩阵)为准。
- Actor 由入口认证产生，业务服务执行统一授权；查询先限定可见范围，再搜索、计数和聚合。实例管理员不自动取得私人空间业务权限。
- SQLite + SQLAlchemy 2 + Alembic；首版每数据目录单业务进程，保留数据库租约和条件更新，不承诺多实例。
- 旧库导入新库：旧整数 ID 映射 UUID，部门映射标签，所有旧账号进入指定 Owner 的导入团队空间。旧口令、会话和共享策略不映射成新版权限。
- 凭证授权代次与轮换版本分离；跨账号额度估算限定当前用户可见资源，不能把全局观察结果混入隔离后的列表。

## 影响与验收

保留额度/续期/备份算法的已有验证，在新边界上逐步迁移；不需要同时重写服务端与桌面业务。P1/P2 必须以临时数据库证明同邮箱跨空间不覆盖、默认互不可见、标签不影响授权，以及旧请求不覆盖重新授权或删除。

该 ADR 确定接口和模型约束，不宣称 P0 已实现用户、权限或数据迁移。
