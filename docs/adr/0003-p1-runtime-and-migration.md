# ADR 0003：P1 核心入口与迁移交付

日期：2026-09-10。状态：采用。

## 决策

P1 交付独立的 `Core(CoreConfig(...))` 组合入口，以及本地运维命令 `cursor-core`。数据库与密钥路径由显式配置提供，构造前不创建文件。每个数据目录由跨平台文件锁独占；初始化、运行、校验和升级使用同一锁，异常退出由操作系统释放。

V2 应用服务负责账号授权、额度查询、明细、续期、快照和当前可见账号的推算。入口提供 Actor，服务对资源操作检查空间成员关系。P1 的 Owner/Admin、view/use 查询边界为 P2 提供基础，完整登录、邀请、授权管理、审计与 HTTP 接入由 P2 实施。

原 `cursor-panel` / `cursor-quota` 暂时保留现有存储和鉴权接口。两条路径共享 Cursor 授权协议、额度组装与错误分类等已有行为，原面板的刷新编排已调用共用的额度查询用例。新库在 P2 身份入口完成前不通过旧共享口令或 P0 模拟后台暴露。

SQLite 使用 SQLAlchemy 2，写事务显式 `BEGIN IMMEDIATE`，开启外键检查；Alembic `0001_core` 是固定 schema 迁移文件，不在未来升级时根据最新 ORM 模型重新创建旧版本。迁移文件放在 Python 包内部，安装 wheel 后仍可执行。

Credential 的 AES-GCM AAD 包含密钥版本、空间、账号、授权代次和凭证版本。密钥检查记录允许启动时发现错误密钥；普通列表无需解密凭证。密钥提供接口可接入系统凭证库，P1 先提供独立文件实现；已有密钥不会被 keygen 覆盖。

账号重新授权使用“当前记录 + 授权代次 + 凭证版本”进行条件更新；续期另验证租约持有人与有效期。正常轮换增加凭证版本但保留授权代次与快照；重新授权创建新代次并使旧快照、明细结果和租约失效。旧请求不创建缺失账号。

快照以数据库为权威，按 `(workspace_id, account_id, generation)` 校验写入；明细缓存按空间、账号、授权代次和账期区分，最多 128 项。套餐观测从本次已授权列表计算，删除、改套餐及不可见账号不会向当前查询提供旧全局观测。

## 旧库导入

源文件要求是停止写入后生成的独立 SQLite 一致备份；存在非空 WAL/journal 时拒绝预检。读取使用只读 immutable 连接，并在读完与导入提交前核对文件摘要。工具不主动调用 Cursor，也不读取旧部署环境中的隐式账号路径。

导入目标必须没有业务账号，且属于指定 Owner 的团队空间。导入事务统一提交账号、加密凭证、标签、快照、旧 ID 映射和导入回执；中途失败整体回滚。同一来源再次导入返回回执，保留后续编辑和删除，不重新建档。

旧快照邮箱/姓名无法唯一对应、Cookie fingerprint 已变化或内容格式无效时跳过并统计。旧管理员会话、共享口令与访客策略不导入。用户身份不从旧账号姓名推断。

回退通过匹配的数据备份和密钥恢复。旧程序不得打开新版数据库，工具不执行破坏性的 schema 降级；新版运行后发生的上游轮换可能要求旧版重新授权。

## 验证

跨空间同邮箱、外键、密文篡改、错误密钥恢复、进程锁、续期心跳/CAS、删除和重新授权竞争、权限变化后的明细、导入回滚/重复执行和 wheel 中的 CLI 流程均有专用测试。结果见 [P1 验证报告](../plans/p1-verification.md)。
