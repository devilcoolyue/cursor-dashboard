# v0.0.4 版本归档

v0.0.4 修复桌面后台启动失败时的二次崩溃、错误信息丢失和重试恢复问题。Python、Web、桌面及随包后台统一为 `0.0.4`；API 主版本保持 `1`，数据库 schema 保持 `0004_retention`。

## 修复内容

- **后台异常退出**：初始化失败时不再由父进程监听线程占用 Python 缓冲流锁，避免解释器退出时再次崩溃并掩盖原始错误。
- **启动诊断**：界面显示脱敏错误分类、异常类型与数字系统错误码，区分依赖加载、目录占用、目录权限、数据读写及本地监听失败。
- **启动日志**：保存最近一次后台启动的版本、构建提交、阶段与脱敏错误。Windows 日志为 `%LOCALAPPDATA%\dev.cursor-panel.desktop\logs\startup.json`；macOS 为 `~/Library/Logs/dev.cursor-panel.desktop/startup.json`。每次启动或重试覆盖上一条记录。
- **重试连接**：后台已退出时重新启动进程，后台仍在运行时继续解锁；启动中的并发重试不会重复拉起进程。
- **账号页面恢复**：重试成功后先加载本地身份，再离开恢复页，避免停留在登录页面。

## 安装与升级

[GitHub Release v0.0.4](https://github.com/devilcoolyue/cursor-dashboard/releases/tag/v0.0.4) 提供 macOS Apple Silicon / Intel、Windows x64、Linux amd64 服务端、Python wheel、源码、校验文件和签名更新产物。

- **可正常打开的 v0.0.2 / v0.0.3 客户端**：在“关于与更新”中检查并安装更新。自动检查提供提示，不自动安装。
- **原先后台无法启动的客户端**：完全退出 Cursor Panel，下载对应平台完整安装程序，手动安装到原位置。保留原应用数据目录及系统凭证库条目。
- **已安装启动修复测试包的同事**：测试包仍显示 `0.0.3`，现在可统一更新到正式编号 `0.0.4`。
- **日志反馈**：若仍无法启动，先保存完整错误截图与 `startup.json`，再点击重试，以免覆盖失败记录。
- **服务端**：本次未增加数据库迁移，已有 v0.0.3 数据库继续使用 `0004_retention`。服务端包随统一版本一起更新；从 v0.0.2 或更早版本升级时仍需遵循 [v0.0.3 升级说明](v0.0.3.md)。

## 验证与边界

先前 Windows 修复测试包通过源码/冻结后台、实际安装启动、日志、异常退出清理和页面恢复测试，用户反馈同事初步恢复可用。调查与测试包证据见[Windows 启动记录](../plans/windows-startup-crash.md)。这些结果不等于已确定原设备第一次初始化失败的具体原因。

正式版本按本次提交重新构建，运行三平台页面、桌面、交付和签名更新包验证；最终运行记录随 Release 验证附件提供。测试使用自有临时数据与合成账号，不替代所有真实设备和账号的业务验收。

桌面产物仍无 Apple Developer ID 签名/公证或 Windows Authenticode；更新包签名验证更新来源，不替代系统发行者签名。真实远程 Cursor 切换继续关闭，Linux 原生桌面和 Windows arm64 不在支持范围。
